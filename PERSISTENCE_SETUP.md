# Постоянная база для Render

Приложение в production использует PostgreSQL. При первом старте оно создаёт таблицу состояния и переносит `data/db.json`, если старый файл ещё доступен в контейнере. Без `DATABASE_URL` сервер намеренно не запускается в режиме production, чтобы не принять новые игровые действия в эфемерную локальную базу.

## Настройка Render

1. Создайте PostgreSQL в том же регионе, что и Web Service.
2. В настройках Web Service добавьте `DATABASE_URL` со значением **Internal Database URL** из PostgreSQL.
3. Оставьте `DATABASE_SSL=false` для внутреннего адреса Render. Для внешнего адреса установите `DATABASE_SSL=true`.
4. Оставьте `DB_POOL_SIZE=10` или задайте меньшее значение с учётом лимита соединений базы.
5. Перезапустите/разверните Web Service и проверьте `/api/health`: поле `storage` должно быть `postgres`.

`DATABASE_URL` — секрет: добавляйте его только в Environment Variables Render, не в репозиторий и не во фронтенд.

Состояние сохраняется в PostgreSQL транзакционно до отправки ответа клиенту. Изображения, загруженные через админ-панель, тоже помещаются в базу (лимит — 2 МБ на изображение). Старые JSON-данные импортируются автоматически только если файл присутствует при первом подключении базы; файловую систему Render нельзя считать резервной копией.

## Игровая экономика

- Апгрейд использует 5% математическую комиссию без искусственного минимума/максимума шанса.
- Шанс кейса распределяется по весам редкости, затем внутри редкости — с поправкой на цену карты.
- Цена кейса рассчитывается по математическому ожиданию и округляется вверх до 50 TC, целевой возврат — не выше 75%.
- Цены новых карт ограничены диапазонами редкости: обычная 50–299, редкая 300–999, эпическая 1 000–4 999, легендарная 5 000–250 000 TC.
- Пополнение выключено до подключения реального платёжного провайдера; API не начисляет баланс по неподтверждённому запросу.
